## Фича: прогресс‑бар на странице расчёта сметы

### Зачем это нужно
Прогресс‑бар решает две проблемы:
- **Для пользователя:** убирает ощущение, что интерфейс «завис» во время расчёта (который может занимать 1–3 секунды из‑за подбора покрытий, расчёта НДС и доставки).
- **Для бизнеса:** снижает процент отказов на странице калькулятора и повышает доверие к инструменту.

### Пользовательские истории (User Stories)
- **US‑PB‑001.** Как пользователь, я хочу видеть прогресс‑бар при запуске расчёта сметы, чтобы понимать, что система обрабатывает данные.
- **US‑PB‑002.** Как пользователь, я хочу видеть понятную подпись к прогресс‑бару («Считаем площадь…», «Подбираем покрытия…»), чтобы понимать текущий этап.
- **US‑PB‑003.** Как QA‑инженер, я хочу проверять прогресс‑бар в сценариях с разной скоростью ответа бэкенда (быстро/медленно/ошибка).
- **US‑PB‑004.** Как разработчик, я хочу, чтобы прогресс‑бар корректно сбрасывался при повторном запуске расчёта.

### Постановка задачи

| Поле | Содержание |
| --- | --- |
| **Цель и проблема** | **Бизнес‑проблема:** пользователи уходят со страницы расчёта, если не видят обратной связи. **Пользовательская проблема:** ощущение «зависания» интерфейса. **Ограничения:** расчёт может занимать 1–3 секунды. **Ожидаемый эффект:** снижение отказов, рост завершённых расчётов. |
| **Для кого (стейкхолдеры и роли)** | **Бизнес/продукт:** владелец продукта, маркетолог (цель — удержать пользователя). **Пользователь:** посетитель сайта (хочет понятный и отзывчивый интерфейс). **Разработчик:** фронтенд‑инженер (реализует логику отображения и сброса). **QA‑инженер:** тестирует сценарии с задержками и ошибками. **Системный аналитик:** фиксирует требования и критерии приёмки. |
| **Реализовать (модули/разделы/процедуры)** | **Модуль UI:** компонент прогресс‑бара с текстовыми статусами. **Модуль оркестрации расчёта:** логика этапов (сбор данных → расчёт площадей → подбор покрытий → расчёт НДС/доставки → финальная сборка). **Интеграция с бэкендом:** обработка ответов, таймаутов и ошибок. **Обработка состояний:** «старт», «прогресс», «успех», «ошибка», «сброс». **Тестовый стенд:** сценарии с эмуляцией задержек и ошибок. |
| **Критерии приёмки (тест‑кейсы)** | **TC‑PB‑UI‑001.** При нажатии «Рассчитать» прогресс‑бар появляется сразу, заполняется до 100% и исчезает после результата. **TC‑PB‑UI‑002.** Подпись меняется по этапам (не статичная). **TC‑PB‑ERR‑001.** При ошибке прогресс‑бар останавливается, показывается понятное сообщение, кнопка разблокируется. **TC‑PB‑RESET‑001.** При повторном расчёте прогресс‑бар сбрасывается в 0%. **TC‑PB‑PERF‑001.** Прогресс‑бар не «зависает» при задержке 1–3 сек, UI остаётся отзывчивым. **TC‑PB‑MOB‑001.** На мобильных устройствах прогресс‑бар отображается корректно. |
